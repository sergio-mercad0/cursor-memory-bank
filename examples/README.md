# Example Memory Bank Files

These are real examples from the **Photo Factory** project—a self-hosted photo/video management system.

## What's Included

| File | Purpose |
|------|---------|
| `PROJECT_BRIEF.md` | Project scope, mission, future capabilities |
| `PRODUCT_ROADMAP.md` | Epic/Workstream/Task hierarchy with status |
| `DECISION_LOG.md` | Architecture Decision Records (ADRs) |
| `LESSONS_LEARNED.md` | Patterns, gotchas, debugging tips |

## How to Use These Examples

1. **Study the Structure:** Each file follows a consistent format
2. **Note the Detail Level:** Observe how specific the content is
3. **Adapt to Your Project:** Use as a starting point, customize for your domain
4. **Keep the Discipline:** The value comes from consistent updates

## Key Patterns Demonstrated

### PROJECT_BRIEF.md
- Mission statement with clear scope
- Problem/Solution table format
- "Future Capabilities" section for architectural awareness
- User personas and success metrics
- Explicit non-goals to prevent scope creep

### PRODUCT_ROADMAP.md
- Hierarchical structure: Epic > Workstream > Task
- Consistent status symbols (✅ 🔄 ⏳ ❌)
- Priority indicators (🔥 📋)
- Checkbox format `[x]` / `[ ]` for tasks
- Timeline/milestone section

### DECISION_LOG.md
- ADR format: Context → Decision → Rationale → Alternatives → Consequences
- Numbered entries (ADR-001, ADR-002, etc.)
- Status tracking (Proposed, Accepted, Deprecated, Superseded)
- Comparison tables for alternatives considered

### LESSONS_LEARNED.md
- Pattern format: What + Code Example + Why
- Gotcha format: Problem + Solution + Code Example
- Categorized sections (Development, Operational, Testing, Performance)
- Concrete debugging tips

---

**Use these as inspiration, not templates.** Your project will have its own unique patterns and decisions to document.
